# MVP 設計書

## 1. 採用する前提

本アプリはゴルフのローカルゲーム「オリンピック」の記録を扱う。一般的な標準ルールとして、4人は金4・銀3・銅2・鉄1、3人は金4・銀3・銅2、2人は金4・銀3とする。メダルはグリーン上の距離順を組で決め、記録者が結果を選ぶ。同じメダルの複数選択を許可する。

割り当てられた位置から1パットでカップインした場合だけ点を獲得し、獲得なしは0点とする。グリーン外から直接カップインしたダイヤは5点。初期値は有効で、ラウンド単位で無効にできる。3パット減点、砂イチ等の派生ルール、金銭換算は扱わない。

## 2. 画面と操作

1. 日付、ホール数、2〜4人の名前、ダイヤ設定を指定し、ラウンドを開始する。
2. ホール番号一覧または前後ボタンでホールを選ぶ。
3. 各プレーヤーカードで「なし / 利用可能なメダル」から結果を選ぶ。選択は同じボタンを再度押しても保持し、別選択で変更する。
4. 各カードにこのホールの獲得点・差引点、ラウンド累計の獲得点・差引点を分けて表示する。
5. ホール別差引合計とラウンド差引合計を表示する。どちらも0となる計算式を使う。
6. 履歴からラウンドを再開または削除する。削除前と JSON 全件置換前に確認する。

## 3. 点数計算

各ホールでプレーヤー i の獲得点を `g_i`、人数を `n` とする。

```text
d_i = g_i × (n − 1) − Σ(g_j), j ≠ i
```

総差引点は `Σ(d_i) = (n − 1)Σ(g_i) − (n − 1)Σ(g_i) = 0`。累計はホールごとの差引点を加算するため、ラウンド全体でも合計0となる。獲得点と差引点は別の UI 欄に出す。

4人で金4点と銅2点を獲得した場合、金のプレーヤーは `4×3−2=+10`、銅は `2×3−4=+2`、他2人はそれぞれ `0×3−(4+2)=−6`。

## 4. 保存形式とプライバシー

ブラウザーの localStorage key は `olympic-score-app.v1`。保存するトップレベル形式は `{ schemaVersion, activeRoundId, activeHole, rounds }`。各ラウンドは識別子、日付、ホール数、プレーヤー名、ダイヤ設定、作成・更新日時、ホールごと・プレーヤーごとのメダル ID 配列を持つ。点数は保存せず、表示時に計算する。

JSON バックアップは `{ format: "golf-olympic-backup", version: 1, exportedAt, activeRoundId, activeHole, rounds }`。復元時はルート、バージョン、ラウンド ID の重複、日付、2〜4人、9 / 18 ホール、ホール配列長、設定に適合するメダル ID を検証する。検証が完了し、利用者が置換確認に同意した後にのみ localStorage を置換する。

ラウンドデータをサーバーへ送信せず、公開リポジトリには利用者の記録を含めない。ブラウザーのデータ消去で記録が失われることを画面と README で知らせ、バックアップを促す。

## 5. ルールデータ

`rules.json` はメダル点数、人数別構成、ダイヤ初期値、説明、計算式を保持する。`index.html` と `app.js` は `./rules.json`、CSS、ロゴを相対パスで読み込み、GitHub Pages の `/olympic/` サブパスで動かす。

## 6. 制約・エラー

- HTML / CSS / vanilla JavaScript / JSON のみ。外部 CDN、実行時ライブラリ、ビルド工程、バックエンドなし。
- 保存容量不足など localStorage 書込失敗時はエラーを表示し、成功したように扱わない。
- JSON の構造や記録が不正な場合は復元せず、既存記録も置き換えない。
- ルール JSON を読み込めない場合は記録操作を開始できないことを知らせる。
- 各ホールの記録は何度でも修正できる。大会スコア、位置情報、現金額は保存しない。
